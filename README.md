# WHAT COULD GO WRONG?

**A Bad Decisions Life Simulator.** A portrait-first, offline, choice-driven life sim for iOS and Android. You are 23, employed, and one decision away from a much more interesting decade.

---

## Why this stack (and not Unity)

You asked me to prefer Unity if I were choosing a stack. I chose **TypeScript + Vite + Capacitor**, and here is the honest reasoning:

| | Why it wins here |
|---|---|
| **One codebase, both stores** | Capacitor wraps the same web build into a real iOS and Android binary. Native plugins for haptics, notifications, share sheet, status bar and (when you add it) in-app purchase are called through a typed bridge. |
| **You can play it right now** | The whole game runs in a browser, so it ships as a LIVE PREVIEW instead of a build you have to install. Unity cannot do that in this environment. |
| **The engine is framework-agnostic** | `src/engine` is pure simulation with zero DOM and zero UI imports. It is fully unit-tested and deterministic. If you later want Unity or Godot for the 3D/particle upgrade, you port the *presentation* and keep the entire content library and rules verbatim — the event schema is already data, not code. |
| **A text-and-illustration game is a text-and-illustration game** | Layout, typography, animation and accessibility are dramatically better on the platform built for them. The visual identity here is vector art generated at runtime, which is pixel-crisp at any density. |
| **Iteration speed** | Adding a scenario is editing one array. No asset pipeline, no prefabs, no rebuild. That matters enormously for a game whose entire value is the volume and quality of its writing. |
| **Native haptics, share, notifications** | All wired through Capacitor with graceful web fallbacks. |

If the decision is non-negotiable, everything below `src/ui` is portable: the content library, the simulation, the save format and the balance simulator all move to C# unchanged in structure.

## Running it

```bash
npm install
npm run dev          # play it in the browser (host 0.0.0.0, portrait column)
npm run build        # typecheck + production bundle into dist/
npm test             # 56 tests: engine, content integrity, screen rendering
npm run content:report   # content inventory + validator output
npx tsx scripts/sim.ts            # balance sim: 120 chaotic lives
STRATEGY=careful npx tsx scripts/sim.ts   # 120 thoughtful lives
```

### Ship to a device

```bash
npm run build
npx cap add ios      # once
npx cap add android  # once
npx cap sync
npx cap open ios     # Xcode → run on device / archive
npx cap open android # Android Studio → build AAB
```

App id `com.whatcouldgowrong.lifesim`. Icons live in `resources/icon.png` and are generated by `node scripts/make-icons.mjs`, which writes valid PNGs using only Node's `zlib` — no binary blobs in the repository.

## Architecture

```
src/
  content/           PURE DATA — the game's actual value
    events/          16 files, 133 cards, 431 authored choices
    npcs.ts          the recurring cast (15 people)
    endings.ts       27 endings
    achievements.ts  35 achievements
    daily.ts         the Daily Dilemma pool
    index.ts         THE COMPOSITION POINT — registry + validator + report
  engine/            PURE SIMULATION — deterministic, DOM-free, tested
    types.ts         every contract, including the declarative Cond/Fx language
    rng.ts           serialisable mulberry32 (the RNG state lives in the save)
    catalog.ts       traits, careers, homes, business types, life stages
    conditions.ts    condition evaluation + effect application
    state.ts         new game, monthly tick, market and business simulation
    engine.ts        event selection, choice resolution, delayed consequences,
                     achievements, endings, life summary
    save.ts          versioned saves, migration, export/import, sharing
    text.ts          {token} resolution against the live save
  ui/                PRESENTATION
    styles.css       the design system
    art.ts           procedural scene illustrations (every environment, in SVG)
    avatars.ts       procedural character portraits
    components.ts    shared fragments (HUD, meters, delta chips)
    screens/         the sixteen screens
    feedback.ts      haptics, synthesised audio, toasts, confetti
    shell.ts         router + the single delegated action bus
  lifecycle.ts       ending a life into the permanent album
  monetization.ts    non-predatory store front
  analytics.ts       the event bus (device-local by default)
  native.ts          Capacitor bridge with web fallbacks
```

**The one architectural rule:** `src/engine` never imports from `src/ui`, and only
`engine.ts` imports from `src/content`. Everything else is data flowing one way.

## Adding content without touching engine code

Add a card to any file in `src/content/events/`:

```ts
{
  id: 'career_salary_spreadsheet',
  title: 'THE SPREADSHEET',
  body: 'Your boss emailed the whole team a salary sheet…',
  art: 'office_spreadsheet',
  cat: 'workplace',          // career|workplace|business|money|investing|romance|
                             // friendship|family|health|housing|travel|social
  weight: 10,                // relative draw weight
  cooldown: 40,              // months before it can appear again
  priority: 2,               // higher jumps the queue when eligible
  rarity: 'common',          // common|uncommon|rare|legendary
  who: 'priya',              // the recurring character attached to this card
  when: { age: [23, 60], career: { employed: true } },
  choices: [
    {
      text: 'Forward it to your personal email',
      hint: 'A small crime',
      tag: 'risky',          // safe|bold|risky|kind|cruel|chaotic|smart|lazy|greedy
      time: 3,               // months this decision consumes
      highRisk: true,
      outcomes: [
        {
          title: 'THAT SEEMED SMART YESTERDAY',
          body: 'It takes four days for somebody to notice.',
          tone: 'chaos',     // good|bad|mixed|chaos|neutral
          fx: { money: -8000, stress: 24, counter: { chaos: 1 } },
          delayed: [
            {
              inMonths: 36,  // fires 3 years after this decision resolves
              chance: 0.6,
              title: 'HR WOULD LIKE A WORD',
              body: 'The audit is not about you. It becomes about you.',
              tone: 'bad',
              fx: { stress: 30, career: -18 },
              queue: [{ id: 'chain_hr_investigation', inMonths: 2 }],
            },
          ],
        },
      ],
    },
  ],
}
```

Then run `npm run content:report`. The validator fails loudly on duplicate ids,
unknown NPCs, unknown endings, unreachable requirements, malformed numbers and
cards that queue an event that does not exist. `npm test` enforces the rest:
every card has 2–4 choices, every choice changes at least one meaningful
variable, no two outcomes share a title, and every `{token}` resolves.

### The delayed-consequence contract

`delayed[].inMonths` is measured **from the moment the decision finishes**, so a
card that consumes six months and schedules a 12-month follow-up lands eighteen
months later. The player sees a `float` beat with no explanation and a single
tease — never the payload. That is the whole game.

## Balance

The simulator runs a full life with a deterministic picker and reports the
distribution. Baseline after tuning (120 lives each):

```
chaotic play   avg age 62, median net worth −$20k   → ruin, debt king, one percent
thoughtful     avg age 80, median net worth $3.8M   → comfortable, long good life
```

82 decisions per thoughtful life while the curve stays hard at the start and
opens up in the last decades.

## Accessibility and platform behaviour

- Honours `prefers-reduced-motion` and ships an in-game motion toggle.
- Larger-text mode and a full-size-text option in Settings.
- Safe-area insets respected top and bottom, portrait-locked on device.
- Haptics and audio are independently toggleable and never required.
- Android hardware back button is wired to in-app navigation.
